# 5. Опыт ИИ-агента: где нейросеть запутается и где не сможет отлаживать

Spark уже лучше большинства движков для агента (headless, JSON, сценарные тесты, MCP). Но есть места, где агент
тратит итерации впустую или делает игру, которая «работает», но неправильно.

## 5.1 Тихие ошибки (самое опасное)

Агент верит выводу `spark check`. Если тот говорит `ok`, агент считает задачу выполненной.

| Ситуация | Что происходит сейчас | Что нужно |
|---|---|---|
| `function Update(dt)` / `function fixedUpdate` / `function Render` | **молча не вызывается**, `ok` [проверено] | Предупреждение «глобальная функция `Update` похожа на колбэк `update`» (уровень error в `check`) |
| `on("colision", f)` | **принимается**, обработчик никогда не сработает [проверено] | Список встроенных событий; для пользовательских — предупреждение, если событие никогда не `emit`-ится |
| `mth.sin(1)` | «attempt to index nil with 'sin'» [проверено] | Строгие глобалы: чтение несуществующего глобала → ошибка «unknown global `mth` (did you mean `math`?)» |
| `cube.postion = ...` | ошибка есть, но без подсказки, с кадрами `__mlua_newindex` [проверено] | did-you-mean по полям + чистка traceback |
| Объект создан, но камера на него не смотрит | игра «работает», на экране пусто | `spark check` предупреждение «0 объектов в кадре камеры», `spark inspect` — «видимые объекты» |
| Объект за пределами света / чёрный | «ok» | эвристики: «сцена слишком тёмная (средняя яркость < 5%)» по скриншоту |
| Объект упал сквозь пол (нет `body` у пола) | «ok» | предупреждение: динамическое тело ушло ниже `y = -100` |

## 5.2 Неоднозначности API (агент выберет не тот вариант)

- `every(s, fn, opts)` и `obj:every(s, fn, times)` — разные третьи аргументы [AUDIT].
- Подсказка бесконечного цикла советует `task.spawn`, а API — `task(fn)` (`spark-script/src/lib.rs:274`) — агент
  напишет `task.spawn` и получит новую ошибку.
- Цвета принимаются строками (`"orange"`, `"#3a3d45"`) и объектами — хорошо, но нет списка имён в ошибке.
- UI: абсолютные пиксели. Агент не знает размер окна заранее → интерфейс съезжает на другом разрешении.
  Нужны якоря (`anchor = "top_right"`) и единицы относительно экрана.
- `draw` как имя колбэка запрещено (есть хорошая ошибка), но `render` для 2D — неочевидно; нужна таблица колбэков в начале
  `SPARK_API.md`.

## 5.3 Где агент не может отлаживать

| Нужно агенту | Сейчас | Что сделать |
|---|---|---|
| Посмотреть живую игру и поменять значение | `spark mcp` умеет только CLI-команды (12 инструментов: new, check, test, screenshot, inspect, golden, doctor, build, docs_refresh, api_search, api_show, guide) | `spark_attach`: пауза/шаг/снимок сцены/`SetObject`/`eval` в запущенной игре |
| Понять, почему FPS упал | нет профилировщика | `spark profile --json`: время Luau/физики/рендера по кадрам, топ функций Luau, GPU-проходы |
| Увидеть промежуточный кадр | headless рендерит только последний кадр | `--screenshot-every` рендерит; по умолчанию в `spark screenshot` рендерить каждый кадр |
| Проверить звук | ничего | `spark check` — список проигранных звуков с временем; `test.sounds()` |
| Проверить UI-клик | `test.tap`, но **нельзя кликнуть по id виджета** | `test.click_ui(id)`, `test.ui()` — дерево виджетов с прямоугольниками |
| Повторить баг | нет записи | `spark record` (ввод + сид) → `--input` файл → регрессионный тест |
| Отличить «игра стоит» от «ждёт ввода» | нет | `test.idle_frames()`, отчёт о задачах в ожидании |
| Детерминизм | `math.random` не сеется | `--seed N`, сид по умолчанию в headless |

## 5.4 Что агенту неудобно

1. **Нет файлов сцен** — агент вынужден строить уровень кодом. Для 200 объектов это 200 строк с магическими
   координатами, которые нельзя визуально поправить и трудно ревьюить. Сцена в тексте (`level1.scene`) + `scene.load`
   сделали бы и ИИ, и человека счастливее.
2. **Нет ассетов «из коробки»**: агент генерирует кубы. Нужна встроенная библиотека CC0-ассетов (с лицензиями, гл. 9) или
   генераторы (`Mesh.rock`, `Mesh.tree`, процедурные текстуры), чтобы игра сразу выглядела прилично.
3. **Документация в одном 55-КБ файле** (`docs/SPARK_API.md`) — съедает контекст. Нужен `llms.txt` с разбивкой по
   темам + `spark api show <тема>` (уже есть поиск — нужны тематические «рецепты»).
4. **Ошибки — строки.** Нужны коды `SPK-1001` с ссылкой на раздел доков и машинным полем `fix`.
5. **Hot reload теряет состояние** — агент не может проверить «после 2 минут игры»; нужен `restore` или снимок состояния.
6. **Нет шаблонов жанров**: `spark new --template` = 3d/2d/empty. Нужны `fps`, `platformer-2d`, `top-down`, `racing`,
   `puzzle` — агенту гораздо проще модифицировать работающую игру.

## 5.5 KPI для агентского опыта (предлагается)

Бенчмарк «агент с нуля»: 20 заданий (от «кубик прыгает» до «платформер с 3 уровнями и меню»), каждое проверяется
`spark test`. Цель: **≥ 80% заданий за ≤ 3 итерации**, 0 «тихих» провалов (игра прошла `check`, но тест не прошёл
из-за опечатки в имени). Прогон — по расписанию в CI с фиксированной моделью, результаты в `docs/dev/agent-bench.md`.
