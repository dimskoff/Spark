# 2. Архитектура как есть и проблемы кода

## 2.1 Карта крейтов

```
spark-cli (spark.exe) ──┬── spark (фасад: App, цикл кадра, devtools-клиент)
spark-editor ───────────┘      ├── spark-core    (World, Scene, Assets, Input, Time, Canvas, UI, события, VFS, FBX/glTF)
                               ├── spark-render  (wgpu)
                               ├── spark-window  (winit, gilrs)
                               ├── spark-audio   (kira)
                               ├── spark-physics (rapier3d)
                               └── spark-script  (mlua/Luau: API, рантайм задач, тесты)
spark-project (game.toml, шаблоны)  spark-devtools (JSON-lines по TCP)  spark-api (реестр API из spark.d.luau)
spark-discord (RPC)
```

**Хорошо:** граф зависимостей чистый, `spark-core` без GPU; бэкенды физики и аудио подключаются через трейты
(`PhysicsBackend`, аудио-бэкенд), поэтому ядро тестируется без железа. Один `run_frame` (`crates/spark-core/src/game.rs:41`)
используют все раннеры — поведение одинаково в окне, headless и в редакторе.

## 2.2 Модель данных

- `World` (`crates/spark-core/src/world.rs`) — «мешок» публичных полей: `scene, assets, input, time, render, physics,
  audio, canvas, branding, animator, window, debug, ui`. Любая система может менять что угодно.
- `Scene` — слот-аллокатор `Object` с поколениями (`ObjectId{index,generation}`), дерево через `parent/children`.
- `Object` — **фиксированный набор полей**: трансформ, `mesh`, `lod`, `material`, `visible`, `body`, `light`.
  Нет компонентов, нет пользовательских данных на стороне Rust, нет тегов/слоёв.
- Ассеты адресуются **индексами** (`MeshId(u32)`, `TextureId`…) и путями; нет GUID, нет метаданных импорта.

## 2.3 Цикл кадра

`input → fixed_update×N (+physics.step) → update → animation → late_update → draw(render) → audio flush → render`.
Переменный `dt` обрезается до 0.1 с, фиксированный шаг с интерполяцией тел (`Interp`). Это правильный дизайн.

## 2.4 Скриптовый слой

`ScriptGame` (`crates/spark-script/src/lib.rs`) держит `World` в `Rc<RefCell<World>>` и **меняет его местами** с
настоящим миром вокруг каждого вызова Luau (`std::mem::swap`, `lib.rs:221-226`). Каждая функция API делает
`with(lua, |w| ...)` → `borrow_mut`.

## 2.5 Архитектурные проблемы (по важности)

| # | Проблема | Почему это плохо | Где |
|---|---|---|---|
| A1 | **Сцена = побочный эффект кода.** Нет сериализации `Scene`/`Object` | Невозможны редактор сцен, префабы, сохранение уровней, git-диффы уровней, «открыть сцену» в MCP | `scene.rs` |
| A2 | **Закрытый набор полей `Object`** вместо компонентов | Каждая новая возможность (частицы, аудио-источник, навигация, скрипт на объекте) = новое поле во всём коде, протоколе, доках, инспекторе | `scene.rs:38` |
| A3 | **Нет reflection-реестра типов** | Инспектор, сериализация, devtools, MCP, доки пишутся вручную в 4-5 местах и расходятся | — |
| A4 | **Источник правды API — рукописный `docs/spark.d.luau`**, а не Rust-код | Регистрация функций (`api.rs`, `types.rs`…) и декларации поддерживаются вручную; drift-тест ловит только расхождения имён | `spark-api`, `tests/api_drift.rs` |
| A5 | **Hot reload = полный перезапуск**: Lua-состояние выброшено, `world.reset()` чистит **все ассеты** | Каждое сохранение заново грузит все модели/текстуры; состояние игры теряется (позиция игрока, меню) | `lib.rs:244`, `world.rs:104` |
| A6 | **Любая ошибка Luau останавливает всю игру** | Ошибка в одном таймере/обработчике = экран ошибки; нет изоляции по задачам/объектам | `lib.rs:197-230` |
| A7 | **`World` — god-object с публичными полями** | Нет границ, нет change-detection; физика и рендер сканируют всю сцену каждый кадр | `world.rs` |
| A8 | **Физическая синхронизация O(n) на каждом шаге с аллокациями** (`Vec`, `HashSet`, `HashMap` под каждый шаг, `world_matrix` с обходом родителей дважды на тело) | 10k тел ≈ 37 мс/кадр | `spark-physics/src/lib.rs:174-327` |
| A9 | **Рендер — один большой «immediate» проход** без render graph; 64 объекта на uniform-окно; 3 атрибута вершины | Потолок качества и производительности (см. гл. 4) | `spark-render/src/consts.rs`, `scene.rs` |
| A10 | **Редактор исполняет игровой Luau в своём процессе** без `catch_unwind` и лимитов | Паника или зависание игры роняет редактор с несохранённым кодом | `spark-editor/src/workspace/viewport.rs:257` |
| A11 | **Монолиты**: `workspace/mod.rs` 1263 строки (раскладка, диалоги, ФС, диспетчер), `fbx.rs` 1247, `assets.rs` 940 | Трудно менять и ревьюить | редактор, ядро |
| A12 | **FBX-парсер внутри `spark-core`** | Ядро без GPU тянет большой небезопасный по входу парсер; правильно — отдельный крейт-импортёр, работающий на этапе импорта | `fbx.rs` |
| A13 | **Нет асинхронной загрузки** | `Model.load` блокирует кадр; для этого даже есть хак «не считать время загрузки в watchdog» (`LOAD_TIME`) | `lib.rs:51-63` |
| A14 | **Headless не рендерит кадры** (только последний) | Скриншоты временных эффектов (motion blur, будущий TAA) неверны; GPU-ошибки в середине прогона не видны | `spark/src/app.rs:512-547` |
| A15 | **Ручной JSON** в `Scene::dump_json` при наличии `serde_json` в зависимостях | Дублирование, риск неверного экранирования, схема не версионирована | `scene.rs:563` |
| A16 | **UI только immediate с абсолютными пикселями** | Нет лейаута, якорей, масштабирования под разрешение, фокуса/клавиатуры, текстового поля, списков | `spark-core/src/ui.rs` |
| A17 | **Разные MSRV**: движок 1.85, редактор 1.95, CI 1.99.1 | MSRV 1.85 нигде не проверяется — заявление не подтверждено | `Cargo.toml`, `rust-toolchain.toml` |

## 2.6 Кодовые проблемы помельче

- `App::max_fps` получил doc-комментарий от `fullscreen` (`crates/spark/src/app.rs:230-231`) — в rustdoc описания перепутаны.
- `report_fatal` пишет `spark-crash.log` **рядом с exe** (`app.rs:281`) — в `Program Files` или в read-only папке не запишется;
  правильно — `%LOCALAPPDATA%/<game>/logs`.
- `ScriptGame::fail` пишет `error.log` **рядом со скриптом** (`spark-script/src/lib.rs:205`) — в упакованной игре это
  виртуальный путь, запись тихо не удаётся; в папке игры с исходниками — мусорит (он даже в `.gitignore`).
- Паник-хук показывает MessageBox на любую панику, включая перехваченные в других потоках.
- `Scene::find` — линейный поиск по имени; `find` в цикле у ИИ-кода = O(n²).
- `world_matrix` обходит родителей заново на каждый вызов (используется физикой и дампом) вместо кэша мировых матриц.
- `Physics::step` создаёт три `mpsc::channel` каждый шаг (`spark-physics/src/lib.rs:321-324`).
- Ошибки — строки (`Result<_, String>`) по всему ядру: нет кодов, категорий и структурированных полей для `--json`.
- Нет `#![forbid(unsafe_code)]` в крейтах, где unsafe не нужен (core, script, project, api, devtools).
- `spark-editor.zip` (320 КБ) закоммичен внутрь `crates/` (см. гл. 8).

## 2.7 Что в архитектуре сделано правильно (сохранить)

- Core без GPU и бэкенды через трейты — тестируемость.
- Единый `run_frame` для всех раннеров.
- Генерационные хэндлы объектов (нет висячих ссылок — проверено: использование уничтоженного объекта даёт понятную ошибку).
- VFS с «тюрьмой путей» и упаковкой в один exe.
- Протокол devtools версионирован.
- Реестр API с генерацией доков и тестом расхождения — правильная идея, нужно перевернуть источник правды (см. гл. 10).
