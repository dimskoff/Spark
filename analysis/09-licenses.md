# 9. Лицензии и авторские права

Это не юридическая консультация; перед релизом 1.0 стоит показать юристу. Но несколько вещей видны сразу.

## 9.1 Что сейчас не так

| # | Проблема | Почему важно |
|---|---|---|
| L1 | **Нет файла уведомлений третьих сторон** (`THIRD_PARTY_LICENSES`). В репозитории единственный файл лицензии — `LICENSE` (MPL-2.0) [проверено поиском] | `spark.exe`, `spark-editor.exe` и **каждая игра из `spark build`** статически содержат код под MIT/Apache-2.0/zlib/BSD (wgpu, naga, winit, rapier3d, parry, nalgebra, mlua, **Luau** (MIT), kira, cpal, gilrs, image, glam, egui…). MIT и Apache требуют распространять текст лицензии и копирайты вместе с бинарником. Сейчас этого нет ни в релизных архивах, ни в собранных играх |
| L2 | Игры пользователей наследуют ту же проблему | Разработчик игры на Spark неосознанно нарушает MIT/Apache, выкладывая игру в Steam/itch |
| L3 | Происхождение ассетов не задокументировано: `figure.glb`, `hit.wav`, `spawn.wav`, логотипы | Если ассет взят из сети без лицензии — нарушение; если сгенерирован — стоит так и записать |
| L4 | Нет проверки лицензий зависимостей в CI (`cargo deny` не запущен) | Можно случайно подтянуть GPL/AGPL-зависимость, несовместимую с закрытыми играми |
| L5 | MPL-2.0 — файловый копилефт: изменённые файлы движка в игре должны быть открыты. В README это сказано, но нет инструкции «как выполнить» для тех, кто форкнул движок | Путаница у пользователей |
| L6 | Шрифт Noto Sans (OFL) — оформлен правильно (`OFL.txt` рядом). Но OFL требует, чтобы текст лицензии шёл и с бинарником, куда шрифт встроен | Добавить в общий файл уведомлений |

## 9.2 Что сделать

1. **`cargo-about`** (или `cargo-deny` + `cargo about generate`) → `THIRD_PARTY_LICENSES.md/.html`:
   - класть в релизные архивы рядом с `spark.exe`;
   - встраивать в бинарник (`include_str!`) и выводить командой `spark licenses`;
   - **`spark build` кладёт `THIRD_PARTY_LICENSES.txt` рядом с exe игры** и в zip; в игре — пункт «Лицензии» доступен
     через `--licenses`.
2. **`deny.toml`** с разрешённым списком: MIT, Apache-2.0, BSD-2/3, zlib, ISC, Unicode-3.0, MPL-2.0, OFL-1.1, CC0-1.0;
   запрет GPL/AGPL/LGPL для кода, попадающего в игру. Шаг в CI блокирующий.
3. **`ASSETS.md`** — таблица: файл, автор, источник, лицензия. Для встроенных в движок ассетов — только CC0/собственные.
4. Для будущей библиотеки ассетов (гл. 5) — только **CC0** (например, Kenney, Poly Haven, ambientCG: все CC0) с сохранением
   ссылки на источник; никаких ассетов из игр, Sketchfab без явной лицензии, «рипов».
5. Для тестовых моделей glTF-Sample-Assets — у каждой своя лицензия (часть CC-BY 4.0 требует атрибуции): хранить
   `LICENSE` рядом с моделью.
6. **Чужие движки как источник:** идеи и алгоритмы использовать можно; код — только с совместимой лицензией и с
   сохранением копирайта. Godot (MIT), Bevy (MIT/Apache), Fyrox (MIT) — копируемый код помечать комментарием
   `// Adapted from <project> (<license>), <url>` и добавлять в уведомления. Код Unity/Unreal (проприетарный, включая
   исходники UE по EULA) **не брать вообще**, даже «посмотреть и переписать близко к тексту».
7. Брендинг: не использовать названия/логотипы Godot, Unity, Unreal, Roblox в продукте и маркетинге так, чтобы это
   выглядело как партнёрство; сравнения — фактические, с датой.
8. `CONTRIBUTING.md`: добавить DCO (`Signed-off-by`) — подтверждение прав контрибьютора на код.
