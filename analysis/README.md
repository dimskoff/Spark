# Полный разбор Spark (ноябрь 2026)

Независимый технический разбор движка Spark: где он сейчас, чего не хватает, какие баги и архитектурные долги,
чем он хуже и чем может быть лучше Godot / Unity / Unreal / Bevy / Fyrox и других, и что делать дальше.

- **Ветка:** `overhaul/phase-0-1` @ `9269188`, Windows 11, Rust 1.99.1 (закреплён в `rust-toolchain.toml`).
- **Что запускалось перед выводами:** `cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings`,
  `cargo test --workspace`, `spark check` на пробных играх с типичными ошибками ИИ, замеры headless на 1k и 10k объектов.
- **Как читать пометки:** **[проверено]** — воспроизведено при этом разборе; **[код]** — видно в коде, ссылка на файл;
  **[AUDIT]** — взято из `docs/dev/audit/AUDIT.md` и сверено с текущим кодом.

## Коротко (одна страница)

**Этап.** Ранняя альфа 0.1: **закрыты фазы 0 и 1a, частично 2**. Это «рантайм + CLI для ИИ», а не движок общего
назначения. Ядро чистое и проверенное (205 тестов зелёные, clippy без исключений), но у движка нет главного, что делает
движок движком для человека: **файлов сцен, префабов, инспектора с записью, гизмо, undo/redo и импорта ассетов**.

**Сильные стороны (лучше, чем у многих):**
1. Один исполняемый файл игры (`spark build`), без браузера и без установки рантайма.
2. Инструменты для агента, которых нет «из коробки» нигде: `spark check --json`, `spark test` со сценариями,
   headless-скриншоты, `--dump-scene-json`, golden-сравнение, MCP-сервер, реестр API с тестом на расхождение доков.
3. Luau — язык, который модели знают по Roblox; маленький императивный API «одним способом».
4. Строгая валидация: NaN, выход за папку игры, неизвестные флаги и поля — ошибка с `file:line`.

**Главные дыры:**
1. **Нет сцены как данных.** Сцена существует только как результат выполнения кода. Отсюда невозможны редактор сцен,
   префабы, сохранение уровня, мердж в git, правка без ИИ.
2. **Редактор — не редактор сцен.** Инспектор только читает, правки живой игры (протокол v2 `SetObject`) редактор не шлёт,
   нет гизмо, undo, сохранения. Человек без кода игру не соберёт.
3. **Графика уровня 2015 года:** одна карта теней без каскадов, CPU-скининг, нормали/ORM в sRGB, 3 атрибута вершины
   (нет tangents/vertex color/UV1), 64 объекта на draw call, нет частиц, декалей, террейна, GI, TAA.
4. **Тихие ошибки для ИИ:** `function Update` (с большой буквы), `on("colision")`, опечатка глобала — **молча
   игнорируются** [проверено]. Это главный источник «игра не работает, а ошибок нет».
5. **Лицензии:** релизы и собранные игры статически содержат MIT/Apache-зависимости (wgpu, rapier, mlua/Luau, kira,
   winit…), но **нигде не поставляется файл уведомлений третьих сторон** — это формальное нарушение условий MIT/Apache.
6. **Безопасность:** devtools без токена в редакторе, Luau без `sandbox`, FBX-парсер с непроверенными индексами,
   `unsafe env::remove_var`.
7. **Производительность:** 10k динамических тел = ~37 мс CPU на кадр [проверено]; физическая синхронизация O(n) на каждом
   шаге с аллокациями; headless-режим не рендерит промежуточные кадры.

**Что делать дальше (первые 3 шага):**
1. Закрыть «тихие ошибки» (строгие глобалы, проверка имён колбэков и событий, did-you-mean) и лицензии
   (`THIRD_PARTY_LICENSES` в релизе и в `spark build`) — это дни работы, а эффект огромный.
2. Спроектировать и внедрить **формат сцены `.spark` (текст, TOML/RON-подобный) + реестр компонентов (reflection)** —
   фундамент для редактора, префабов, MCP и сохранений.
3. Сделать редактор **редактором сцены**: иерархия + инспектор с записью + гизмо + undo + сохранение сцены,
   работающие поверх той же модели команд, которую использует MCP (человек и ИИ делают одно и то же).

Подробный план — в [11-roadmap.md](11-roadmap.md).
