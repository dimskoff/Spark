# 4. Графика: почему сейчас не получится «реально красивая» игра

Spark сегодня даёт аккуратную low-poly / стилизованную картинку: PBR-сферы, небо с IBL, bloom + ACES, SSAO. Этого
хватает для прототипов и казуальных 3D-игр. Для картинки уровня современных инди на Godot 4 / Unity URP не хватает
целого слоя систем. Ниже — что именно мешает, по влиянию на итоговое изображение.

## 4.1 Что больше всего портит кадр

| # | Проблема | Как выглядит в игре | Что сделать |
|---|---|---|---|
| G1 | **Одна карта теней солнца без каскадов**, 3×3 PCF, покрытие по умолчанию 40 м | Вблизи тени «лесенкой», вдали теней нет, при движении камеры тени дрожат | CSM 3-4 каскада со стабилизацией (snap к текселю), PCSS/Poisson-фильтр, normal offset bias |
| G2 | **Нет глобального освещения** | Помещения плоские, нет отражённого света, «пластиковость» | Сначала: light probes (SH) + запечённые lightmaps (UV1); потом SSGI/DDGI-подобные пробы |
| G3 | **Нет TAA** (только FXAA) | Мерцание тонких деталей, листвы, specular-алиасинг | TAA с motion vectors (motion vectors уже частично есть для motion blur) |
| G4 | **Data-текстуры в sRGB** (R1) | Нормали «плывут», металл/шероховатость неверны | Загружать normal/ORM/metal/rough как `Rgba8Unorm`, мипы в линейном пространстве |
| G5 | **Нет tangents, vertex colors, UV1** (вершина = позиция+нормаль+UV, `consts.rs:8`) | Normal-map на зеркальных UV ломается (тангенты из производных), нельзя лайтмапы, нельзя покраску вершин | Расширенный формат вершин (tangent.w, color, uv1), отдельные потоки |
| G6 | **CPU-скининг, нет morph targets** | Мало анимированных персонажей; нет лицевой анимации | GPU-скининг (storage buffer матриц), morph targets |
| G7 | **Неполный glTF PBR** (R3) | Модели из Sketchfab/Blender выглядят хуже, чем в Blender | Все текстуры glTF + `KHR_texture_transform`, `KHR_materials_emissive_strength`, `clearcoat`, `transmission` |
| G8 | **IBL из LDR, без prefilter/BRDF LUT** | Отражения грубые, металл тусклый | HDR-кубмапы (.hdr/.exr), GGX prefilter, BRDF LUT, reflection probes |
| G9 | **Нет частиц** | Нет огня, дыма, искр, магии, дождя — сразу «пустой» мир | GPU-частицы (compute) с простым описанием в Luau и в сцене |
| G10 | **Нет декалей, террейна, воды, растительности** | Открытые миры и уровни выглядят собранными из коробок | Декали (deferred/clustered), heightmap-террейн с splat, инстансинг травы, простая вода |
| G11 | **Нет объёмного тумана/атмосферы** | Нет «воздуха», лучей света | Physically based atmosphere + volumetric fog (froxels) |
| G12 | **64 света на пиксель без кластеров, 8 теневых источников** | Падение FPS при многих лампах, ночные сцены ограничены | Clustered forward+ |
| G13 | **Тонмаппинг не по умолчанию, нет авто-экспозиции** | Новичок/ИИ получают пересвеченную или тусклую картинку | ACES/AgX по умолчанию, авто-экспозиция, пресеты «Low/Medium/High/Ultra» |
| G14 | **Нет сжатых текстур (KTX2/BC7/ASTC)** | Большие игры упираются в VRAM и размер exe | KTX2 + Basis Universal при импорте |

## 4.2 Почему это сложно именно сейчас

1. **Нет render graph.** Каждый новый проход (TAA, CSM, SSR, частицы) вкручивается вручную в `scene.rs`/`post.rs`,
   управление ресурсами и барьерами ручное. Нужен лёгкий граф проходов до роста фич.
2. **Uniform-окно на 64 объекта** (`MAX_INSTANCES`) ради совместимости с GL. Нужен путь storage-buffer
   (Vulkan/DX12/Metal) с fallback на uniform для GL.
3. **Нет импорта ассетов.** Без этапа импорта (кэш, генерация мипов, сжатие, тангенты, лайтмап-UV) качественные
   ассеты невозможны или медленно грузятся в рантайме.
4. **Нет GPU-профилировщика проходов** — невозможно доказать, что фича укладывается в бюджет.
5. **Golden-тесты на CI не блокирующие** (`continue-on-error` в `ci.yml`): регрессии картинки не ловятся.

## 4.3 Порядок работ (Renderer 2.0)

| Шаг | Что | Критерий готовности |
|---|---|---|
| 1 | Линейные data-текстуры, расширенный формат вершин, полный glTF PBR | golden-тест «DamagedHelmet»-подобной модели (с лицензией CC-BY, см. гл. 9) совпадает с эталоном |
| 2 | Тонмаппинг по умолчанию, авто-экспозиция, пресеты качества | одна строка `graphics.preset = "high"` даёт хорошую картинку |
| 3 | CSM + стабилизация, мягкие тени | нет дрожания при движении камеры (тест: разность кадров) |
| 4 | GPU-скининг, morph targets | 100 анимированных персонажей ≥ 60 FPS на GTX 1060-классе |
| 5 | Render graph + storage-buffer инстансинг + depth pre-pass | 10k объектов ≥ 60 FPS, таблица времени проходов |
| 6 | TAA + motion vectors; mip-chain bloom | нет шиммера (тест кадров) |
| 7 | HDR IBL, reflection probes, light probes | эталонные скриншоты интерьера |
| 8 | GPU-частицы, декали | пример `examples/10-particles` |
| 9 | Clustered lighting | 256 ламп ≥ 60 FPS |
| 10 | Террейн, вода, трава, атмосфера, volumetric fog | showcase «open world» |
| 11 | Лайтмапы (запекание в редакторе), затем SSGI/пробы | showcase «интерьер» |

Каждый шаг: golden-скриншот с допуском на lavapipe + замер на реальном GPU в таблице профилей.

## 4.4 Чего не делать

- Не гнаться за Nanite/Lumen/RT: wgpu не даёт аппаратного RT, а для целевой аудитории (ИИ-игры, инди) выигрыш от
  CSM+TAA+проб на порядок выше.
- Не делать node-граф материалов раньше, чем есть сцены и редактор: Spark-путь — WGSL-сниппеты + параметры, которые ИИ
  пишет легко.
