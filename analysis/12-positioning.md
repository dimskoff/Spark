# 12. Позиционирование: чем Spark может выделиться

## 12.1 Ниша

Не «ещё один Godot», а **«движок, в котором ИИ и человек делают одну и ту же игру одними и теми же действиями»**:

- ИИ пишет код и сцены → `spark check/test/screenshot` доказывают результат;
- человек открывает ту же сцену в редакторе, двигает гизмо, правит свойства — изменения ложатся в тот же текстовый файл;
- агент видит действия человека (журнал команд) и наоборот.

Ни у Godot, ни у Unity, ни у Bevy/Fyrox нет этого как **встроенного дизайна** — у них ИИ прикручен плагинами.

## 12.2 Пять отличий, которые стоит довести до «лучше всех»

1. **Проверяемость:** каждый аспект игры можно проверить без окна — картинка, сцена, звук, UI, производительность.
2. **Строгость без тишины:** ноль «тихих» ошибок; каждая ошибка с кодом, местом, подсказкой и ссылкой.
3. **Один файл игры, мгновенный старт:** `spark new` → играть за 1 секунду; exe < 25 МБ.
4. **Текстовые сцены, дружелюбные к git и ИИ.**
5. **Готовые жанровые шаблоны и CC0-ассеты:** первая игра выглядит прилично, а не «кубики».

## 12.3 Чего не делать

- Не соревноваться с Unreal в фотореализме и с Unity в количестве платформ.
- Не переходить на ECS-API для пользователя (Luau-объекты и компоненты проще; ECS можно держать внутри, если понадобится).
- Не добавлять второй язык скриптов, второй UI, второй способ ввода: «одним способом» — главное преимущество для ИИ.
- Не расширять API без записи в реестр, тестов и доков.
- Не делать облачные/платные фичи частью ядра.

## 12.4 Метрики успеха

| Метрика | Цель к 1.0 |
|---|---|
| Агентский бенчмарк (20 заданий) | ≥ 80% за ≤ 3 итерации, 0 тихих провалов |
| Человек делает игру в редакторе без кода, кроме скриптов поведения | сценарий из гл. 6 проходит |
| 10k объектов / 1k физических тел / 100 анимированных персонажей | ≥ 60 FPS на GTX 1060-классе |
| Размер пустой игры | ≤ 25 МБ |
| Холодный старт | ≤ 1 с |
| Golden-тесты | блокирующие в CI на 3 ОС |
