# 6. Редактор и работа человека без ИИ

## 6.1 Короткий ответ

**Может ли человек сделать полноценную игру в Spark Editor без ИИ, как в Godot?** — **Нет.**
Человек может *написать* игру кодом в редакторе (это IDE с подсветкой Luau, консолью, запуском и отладочной панелью),
как в LÖVE или PICO-8. Но **собрать сцену мышкой — нельзя**: нет сцен, нет записи свойств, нет гизмо, нет undo,
нет сохранения. Сам README редактора прямо говорит: «It is **not** a scene editor».

**Есть ли сцены, чтобы человек всё сделал в редакторе?** — **Нет.** В движке нет формата сцены. «Scene tree» в
редакторе — это просмотр того, что игра создала кодом в данный момент, а инспектор (`workspace/game.rs:657`) только
показывает поля.

## 6.2 Что есть в редакторе сейчас

- Менеджер проектов (недавние, новый из шаблона, открыть), EN/RU.
- Докуемые панели (egui_dock): проводник, редактор кода с подсветкой Luau, консоль, problems (`spark check`),
  отладчик/статистика, дерево сцены, вьюпорт.
- Вьюпорт: игра запускается **в процессе редактора** на его GPU, fly-камера, Play/Pause/Step/Stop.
- Превью: изображения (зум, пипетка), звуки (волна), glTF (орбита, анимации).
- F5 — запуск игры отдельным процессом с live-link (статистика, сцена, пауза/шаг/перезагрузка).

## 6.3 Проблемы редактора

| # | Проблема | Последствие |
|---|---|---|
| E1 | Инспектор только на чтение; протокол v2 `SetObject` реализован в игре, но редактор его **не шлёт** | Даже поправить позицию объекта в живой игре нельзя |
| E2 | Нет формата сцены → нечего сохранять | Любая правка в редакторе исчезнет при перезапуске |
| E3 | Нет гизмо перемещения/вращения/масштаба, нет выделения кликом (хотя `Scene::pick` есть) | Нельзя «расставить уровень» |
| E4 | Нет undo/redo, стека команд | Нельзя безопасно экспериментировать |
| E5 | Нет браузера ассетов с drag&drop в сцену и инспектор, нет импорта | Модели и текстуры подключаются только кодом |
| E6 | Нет редактора материалов, анимаций (таймлайн), UI-дизайнера, частиц | Вся «художественная» работа — только код |
| E7 | Игра во вьюпорте работает в процессе редактора без `catch_unwind` и лимитов | Бесконечный цикл/паника игры = потеря несохранённого кода |
| E8 | Нет автодополнения/hover/go-to-definition (есть только подсветка) | Писать руками медленно; `docs/api.json` можно использовать для автодополнения |
| E9 | Нет отладчика Luau (брейкпоинты, watch, стек) | Отладка только `print` |
| E10 | Нет профилировщика | Невозможно найти тормоза |
| E11 | `workspace/mod.rs` 1263 строки: раскладка, диалоги, ФС, диспетчер в одном файле | Трудно развивать |
| E12 | Иконки-эмодзи, плотность, раскладка по умолчанию не как в движках (есть в `docs/dev/EDITOR_PROMPT.md` как жалоба владельца) | Ощущение «самоделки» |
| E13 | Нет окна настроек с поиском, keymap, командной палитры | Неудобно для ежедневной работы |
| E14 | Нет UI для `game.toml`, сборки, тестов | Нужно идти в терминал |
| E15 | Devtools без токена | Безопасность (гл. 3) |

## 6.4 Как сделать, чтобы человек мог всё в редакторе

Ключевая идея: **человек и ИИ работают через одну модель команд.** Каждое действие редактора — команда
(`Spawn`, `SetProperty`, `Reparent`, `Delete`, `AssignMaterial` …), которая:
1. применяется к документу сцены (файлу), а не к живой игре;
2. обратима (undo/redo);
3. доступна через MCP — агент делает то же, что человек, и видит то же самое.

Минимальный вертикальный срез («редактор MVP»), который надо довести до конца прежде всего остального:

1. Формат сцены `.scene` (см. гл. 10) + `scene.load("levels/1.scene")` и `spawn(prefab)` в Luau.
2. Иерархия: создание, удаление, дублирование (Ctrl+D), переименование (F2), drag&drop-перепривязка, мультивыбор.
3. Инспектор с записью, генерируемый из реестра компонентов: Transform, Mesh, Material, Body, Light, Camera, Script.
4. Вьюпорт сцены (не игры): выделение кликом, гизмо W/E/R, снап, фокус F, сетка.
5. Undo/redo на всё; сохранение Ctrl+S; «грязная» звёздочка.
6. Play-in-editor: запуск игры **отдельным процессом** из текущей сцены, возврат к исходной сцене после Stop.
7. Браузер ассетов: drag&drop модели в сцену и текстуры в материал.
8. Скрипт на объекте: поле `script = "src/door.luau"` с колбэками `start(self)`, `update(self, dt)` — привычная людям
   модель (как в Godot/Unity), остающаяся простой для ИИ.

**Критерий готовности:** человек без правки файлов создаёт проект, ставит 20 объектов, назначает материалы, двигает
гизмо, правит с undo, запускает, ставит паузу, видит ошибку и собирает exe. Сценарий записан в
`crates/spark-editor/README.md` со скриншотами.

## 6.5 Чего не делать в редакторе

- Не превращать его в Unity по объёму. Держать «одна сцена, одна иерархия, один инспектор», всё остальное — плагины позже.
- Не хранить состояние сцены только в редакторе: файл сцены — единственный источник правды, редактор — его вид.
- Не встраивать движок игры в процесс редактора для Play (оставить вьюпорт сцены в процессе, игру — отдельно).
