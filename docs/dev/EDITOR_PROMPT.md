# Промпт: полный редизайн и доработка Spark Editor

Ты работаешь над `crates/spark-editor` (Rust, egui/eframe 0.36, egui_dock) в репозитории Spark (`C:\Users\Dimsk\Documents\GitHub\Spark`, ветка `overhaul/phase-0-1`; в `main` не пушить, без force-push). **Цель: полноценный редактор уровня Godot / Unity / Unreal**, в котором люди делают игры целиком: собирают сцену, смотрят и правят объекты, назначают материалы, анимируют, запускают, отлаживают, профилируют, экспортируют — без ручной правки файлов. Мне не нравятся нынешний интерфейс, стилистика, мало настроек и лишние «залупы» — переработай всё: вид, раскладку, поведение. Агент тоже должен мочь управлять редактором (через MCP / devtools).

Работай фазами, каждая — проверяемый результат (скриншот окна редактора, тест, запись в `crates/spark-editor/README.md`). Тесты запускай редко и разом (экономь лимиты). Скриншоты окна делай через computer-use / встроенный браузер не нужен: используй `cargo run -p spark-editor` и снимок экрана. Код/доки на английском, общение на русском. Ничего не удаляй без записи причины в `docs/dev/audit/CLEANUP.md`.

## Фаза 1 — каркас и стиль
- Новая раскладка по умолчанию (как у движков): слева **Hierarchy** (дерево сцены) + вкладка Explorer/Assets; по центру **Viewport/Game/Code** вкладки; справа **Inspector**; снизу **Assets browser / Console / Problems / Profiler**. Верхняя панель: меню (File/Edit/View/Project/Run/Help), по центру Play/Pause/Step/Stop (Play-in-editor + «eject»: править живую сцену), справа выбор раскладки/пресета качества. Статус-бар: состояние игры, FPS, объекты, GPU. Сохранение/сброс раскладок (несколько пресетов: Scene, Code, Debug).
- **Окно настроек** (Ctrl+,) с поиском: General (язык, тема, акцент, масштаб UI, плотность, шрифт UI), Editor (шрифт/размер кода, tab width, word wrap, автосохранение, форматирование, минимап), Viewport (камера, скорость, сетка, гизмо, снап), Run (флаги запуска, `--size`, devtools), Keymap (редактируемые горячие клавиши, поиск конфликтов), Paths (spark, luau-lsp), Experimental. Настройки в `settings.json`, версионируются, миграции, экспорт/импорт.
- Командная палитра (Ctrl+Shift+P / Ctrl+P поиск файлов), всплывающие подсказки, тосты, диалоги подтверждения, drag&drop везде, контекстные меню (ПКМ) на каждом элементе.
- Без паник: `catch_unwind` вокруг игры во вьюпорте (сейчас Luau работает в процессе редактора без защиты и лимита памяти), автосохранение/восстановление после сбоя.

## Фаза 2 — сцена и инспектор (главное)
- Devtools протокол v2 уже умеет `SetObject` на стороне игры (`crates/spark/src/devtools.rs`), редактор его не шлёт. Допиши: выдача токена (`SPARK_DEVTOOLS_TOKEN`, проверка `Hello.token`), `SetObject`, затем расширь протокол (версионируй, лимиты, тесты): `Select`, `Spawn`/`Duplicate`/`Delete`, `Reparent`, `SetMaterial`, `SetLight`, `SetBody`, `SetCamera`, `GetObjectDetail` (материал, меши, коллайдеры, свет, пользовательские данные).
- **Hierarchy**: дерево с drag&drop (перепривязка), мультивыбор, поиск/фильтры (по типу, тегу), иконки по типу, видимость/блокировка, переименование (F2), дублирование (Ctrl+D), удаление, группировка, цвета.
- **Inspector**: секции Transform / Mesh / Material (цвет, PBR, текстуры с превью и drop из ассетов, blend, shader + его параметры) / Physics (тело, форма, масса, трение, слои) / Light / Camera / Script data. Редактируемые поля (DragValue с шагом/Shift/Ctrl, слайдеры, color picker, vec3 с локом пропорций, выпадающие списки), reset-кнопки, мультиредактирование.
- **Undo/Redo на всё** (Ctrl+Z/Y): единый стек команд; правки живой сцены обратимы; история видна в панели.
- **Вьюпорт**: fly-камера + orbit, фокус на объекте (F), сетка/оси, **гизмо** перемещения/вращения/масштаба (W/E/R, локальные/мировые, снап), выделение кликом (pick по мешам, есть `Scene::pick`), рамки bounds/коллайдеры/нормали/wireframe/overdraw оверлеи, режимы отладки (albedo, normals, roughness, AO), Play-in-editor с паузой/шагом.
- Сценовые файлы: сначала проектируй формат (см. `docs/dev/ROADMAP.md`, Phase 3: сцены/префабы — ADR!) — редактор должен сохранять сцену в человекочитаемый файл, который движок загружает (`scene.load`), префабы с override'ами.

## Фаза 3 — ассеты, материалы, код, анимация
- **Assets browser**: сетка/список, превью (модели с вращением, звуки, шрифты, материалы), метаданные импорта, drag&drop в сцену/инспектор, поиск/теги, ссылки «где используется», переименование с обновлением ссылок, импорт (glTF/FBX/изображения/аудио).
- **Материалы/шейдеры**: редактор материала с живым превью; WGSL-редактор с подсветкой и ошибками (`spark check`), шаблоны, node-граф (позже).
- **Код**: Luau-редактор — подсветка, автодополнение/hover из `docs/api.json` (реестр API, `spark_api::api()` можно использовать напрямую как крейт), переход к определению, поиск по проекту, замена, форматирование, диагностика из `spark check --json` по мере набора, сворачивание, мини-карта, вкладки с закреплением, split view; отладчик: точки останова, watch, стек (нужна поддержка в `spark-script`), REPL в запущенной игре.
- **Анимация/эффекты** (после ядра): таймлайн и кривые, state machine, частицы, UI-дизайнер, terrain — как отдельные этапы с ADR.

## Фаза 4 — диагностика и проект
- Профайлер (CPU по системам, GPU по проходам, память, кадровая история, flame graph), инспектор draw calls / render graph, консоль с фильтрами/поиском/копированием, лог физики и событий, тесты (`spark test`) с запуском из UI и показом падений со ссылкой на строку, golden-скриншоты рядом (`spark golden`, `spark diff`).
- Мастер создания проекта (шаблоны 3d/2d/empty + примеры из `examples/`), настройки проекта (`game.toml` формой), диалог сборки/экспорта (`spark build`, платформы), менеджер версий движка, обновление.
- **ИИ-интеграция**: панель агента (подключение внешнего агента через MCP `spark mcp`), журнал действий агента с откатом каждой операции, режим «предложение → превью → применить», запись GIF/видео сессии.

## Качество и приёмка
- Скриншотные тесты окна (egui_kittest или свой headless-harness), сценарные тесты редактора, `cargo clippy -D warnings`, `cargo fmt`, локализация en/ru для каждой строки (тест на отсутствующие ключи), доступность (фокус, клавиатура), производительность (без перерисовки при простое, 60 FPS на сцене из 10k объектов в иерархии — виртуализация списков).
- Критерий готовности: человек без правки файлов создаёт проект из шаблона, добавляет объекты, назначает материалы, двигает гизмо, правит свойства с undo/redo, запускает в редакторе, ставит паузу, видит ошибки и профиль, собирает exe. Покажи это скриншотами и записью сценария в `crates/spark-editor/README.md`.
- Каждая фаза: коммиты маленькие, `git push` в ветку, обновление `STATE.md`. Если лимит заканчивается — сначала `STATE.md`, потом коммит.
